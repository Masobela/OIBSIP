========================================
10. TEST RESULTS
========================================
CONFIRMED
- UFW installed and version 0.36.2 verified.
- Default policies and all four rules present in UFW status output.
- Firewall active after "ufw enable".
- Connectivity between the VMs (0% packet loss).
- SSH listening on Kali.
- Metasploitable 2 connected to Kali TCP 22 (nc reported "open").

INCONCLUSIVE
- TCP 80 test: no response received and the command did not complete.
  Not enough to prove the firewall blocked it, because:
    * no check showed that an HTTP service was listening on Kali port 80
    * the same test was not repeated with the deny rule removed
    * the way the command ended is not shown on screen
- TCP 22 "Connection refused" (before SSH was started): shows the port
  was reachable but nothing was listening. On its own it does not
  confirm the firewall rule.

NOT TESTED
- TCP 443 and TCP 21 connection tests.
- IPv6 rules.
- Behaviour of the outgoing policy beyond the successful ping.

========================================
11. INTERPRETATION (NOT DIRECTLY OBSERVED)
========================================
- The "Connection refused" replies before SSH was started suggest packets
  reached Kali, which is consistent with the allow rule on TCP 22.
- The silent result on TCP 80 is consistent with a deny (drop) rule.
  A closed port with no firewall normally answers "Connection refused"
  quickly. This is an explanation, not proof.
- With default incoming = deny, the explicit deny rules for TCP 80 and
  TCP 21 are redundant for blocking. They document intent.

========================================
12. CONCLUSION
========================================
UFW was configured with a deny-by-default incoming policy and four rules
(allow 22, deny 80, allow 443, deny 21), enabled, and verified with
status output. SSH access from Metasploitable 2 worked once the SSH
service was running. The TCP 80 test gave no response, which is
consistent with the deny rule but is inconclusive on its own.
